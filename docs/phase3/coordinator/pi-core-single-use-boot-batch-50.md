## What the runner can consume

The [build seal](../../../packaging/pi-core/immutable-host-b50/build-seal.json)
is public and empty; the [default release](../../../packaging/pi-core/immutable-host-b50/owner-release.json)
must contain zero slots. The [offline builder](../../../scripts/prepare_pi_core_single_use_owner.py)
also implements a separate, build-only route for a future **exactly one-slot**
private release. No code rewrite, run-time manifest, environment switch or
credential is needed to turn the private records into build inputs. A normal
Git signature alone grants no authority:

1. The custodian must first verify the original signed nomination,
   enrollment and boot decision records, the exact host, cost/window,
   firmware policy, network isolation, custody and release owner. The signed public seal
   carries only distinct record digests and the canonical private release
   digest. These hashes do not verify the underlying decisions' signatures.
2. On a trusted checkout, the [build gate](../../../scripts/pi_core_boot_build_seal.py)
   takes the independently trusted release signer and full approved source
   commit, reads the seal from that commit, and compares every declared
   source snapshot to its signed bytes **before** opening the sealed local
   private release. The checked-in seal refuses here. The assembly uses
   private generated bytes rather than placing private data in compiler
   arguments. A private build and its embedded manifest must stay in custody.
3. The [native runner](../../../packaging/pi-core/immutable-host-b50/owner-runner.m)
   matches the embedded slot's UUID, nominated host UUID digest, absolute fixture,
   physical directory and file identities, B44 disk, enrolled store and full
   firmware policy. On its exclusively held fixture it reserves the attempt
   directory **once**, syncs the parent before touching target media, and never
   removes the reservation—even on failure. The B47 supervised start site
   rechecks the half-open UTC window and its non-extendable monotonic deadline
   after ARM, on the machine queue. The isolated device graph, recorder,
   stop observer and 180/15/15-second bounds are reused unchanged.

The host digest is SHA-256 of the lowercase hyphenated macOS host UUID text,
not proof of cloud account, exclusive placement, correct clock or asset ownership.
Those facts require independent nomination. At-most-once assumes a trusted,
non-rewound host and retained fixture/ledger; host loss, rollback, or an erased
reservation means **hold, not retry**. The local ad-hoc signature is not
Developer ID/notarization or target distribution approval.

## What the matching verifier proves

The [offline verifier](../../../scripts/replay_pi_core_single_use_owner.py)
authenticates the artifact commit and exact build-seal bytes. For a future
singleton it also requires the same seal in an earlier signed ancestor from
the same trusted Git signer, the private release matching all four digests,
and independently retained pre-attempt bindings. It joins the original B48
archive to the B50 consumption identity, B47 owner events and terminal,
raw serial bytes, B47 watchdog decision, and the two pre-start clock samples.
A start too close to expiry to place unambiguously is indeterminate. Replay
establishes historical consistency, not present authority, independent guest
boot, worker/sensor health, restoration, permission to retry, or qualification.
B47/B48 behavior stays unchanged; partial records and host loss stay unresolved.
